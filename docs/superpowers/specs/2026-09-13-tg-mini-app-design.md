# Мини-апп Центра ДПО в Telegram – проект

Дата: 13.09.2026. Состояние кода на момент написания: `93a707c`.
Автор решений – владелец, ответы получены в разговоре 13.09.2026.

## 1. Что строим

Мини-приложение Telegram: витрина программ Центра ДПО, карточка программы
и заявка на покупку. Первый этап – демо на публичном зеркале без сервера:
витрина и форма работают по-настоящему, отправка заявки показывает честный
демо-экран и ведёт на настоящую оплату в hse.ru.

Образец, который показал владелец, – мини-апп магазина `@border_rubot`,
открытый ссылкой `t.me/border_rubot?startapp=c_campaignyuriy2`: витрина
внутри Telegram и метка рекламной кампании в параметре `startapp`.

| Вопрос | Решение |
|---|---|
| Что происходит при покупке | Заявка плюс ссылка на оплату в корзину hse.ru |
| Что внутри | Витрина программ: сферы, поиск, карточка, заявка |
| Где живёт | Сначала демо на GitHub Pages рядом с витриной сайта |
| Отправка заявки в демо | Честный демо-экран, данные не покидают телефон |
| Способ сборки | Страница `tg/` из генератора в этом репозитории |
| Облик | Направление А – облик сайта целиком в любой теме Telegram |
| Движение | С анимацией |

## 2. Границы

В этот этап **не** входят: приём заявки на сервере, проверка подписи
`initData`, уведомление менеджерам в Telegram-чат, сообщения бота на
`/start`, оплата внутри Telegram, корзина на несколько программ.

Мини-апп не отправляет по сети ни одного байта персональных данных и не
пишет их в `localStorage`/`sessionStorage`. Метка кампании хранится в памяти
страницы.

## 3. Устройство

### 3.1 Файлы

| Файл | Что это |
|---|---|
| `scripts/build-tg-app.js` | генератор: `.catalog-data.json` → `tg/index.html` |
| `tg/index.html` | сгенерированная страница, руками не править |
| `tg/tg-app.css` | стили мини-аппа |
| `js/tg-core.js` | чистая логика без DOM: разбор `startapp`, проверка заявки, фильтр, цена |
| `js/tg-app.js` | экраны, стек «назад», мост к Telegram WebApp |
| `lib/static-http.js` | `tg` добавляется в `PAGE_DIRS` |
| `docker/nginx.conf` | узкий проход `^/tg/[^/]+\.(html|css)$`, как у `programs/` |

Ссылка на оплату берётся из уже экспортируемой `buildPayUrl`
(`scripts/build-program-pages.js`), формула остаётся одна. Выносить её в
`lib/` не нужно: экспорт уже есть, генератор страниц программ запускает
сборку только при `require.main === module`.

### 3.2 Данные на странице

Каталог встраивается в `<script type="application/json" id="tg-data">`.
Каждый `<` в JSON заменяется на `\u003C` (тот же приём, что в блоке «Топ-5»
после аудита 13.09.2026). На страницу уходят только поля экранов:

`id`, `title`, `sphere` (id сферы из `lib/program-spheres.js`), `badge`
(`docBadge`), `doc` (название итогового документа из подсказки `docBadge`),
`format` (`shortFormat`), `duration`, `hours`, `startLabel` (`upcomingStartLabel`
из `lib/hse-catalog.js` – единая подпись «Старт: …» всех витрин сайта:
прошедшей или неизвестной даты нет вовсе, «уточняется» не подставляется),
`price`, `oldPrice`, `tagline`, `audience` (до 5), `results` (до 5),
`modules` (название и часы), `cover` (полная обложка или `null`), `thumb`
(миниатюра, иначе полная обложка), `pay` (ссылка оплаты или `null` для
программ без числового id).

Не уходят: преподаватели, отзывы, FAQ, файлы, скидки, служебные поля
(`source`, `locked`).

Типографика: длинное тире U+2014 в текстах каталога заменяется на короткое
U+2013 при генерации.

### 3.3 Экраны

Одна страница, экраны сменяются без перезагрузки, стек «назад».

1. **Витрина.** Подпись «Факультет права НИУ ВШЭ», заголовок «Программы
   Центра ДПО», поиск по названию и описанию, чипы «Все» и шесть сфер со
   счётчиками, карточки: обложка с пометками документа и формата, название,
   цена, дата старта.
2. **Программа.** Обложка, пометки, название, описание, факты (старт,
   формат, длительность, документ), «Для кого», «Чему научитесь», модули с
   часами. Главная кнопка: «Подать заявку · <цена>».
3. **Заявка.** Карточка программы, поля имя, фамилия, телефон, e-mail,
   должность и место работы – два необязательных поля, как `position` и
   `company` на сервере. Согласие – отдельная непредустановленная галочка с
   текстом формы сайта и ссылкой на `privacy.html`. Имя и фамилия подставляются из
   `initDataUnsafe.user`, если открыто в Telegram. Главная кнопка:
   «Отправить заявку». Проверка полей и тексты ошибок – те же, что у `parseApplication` на сервере.
4. **После отправки (демо).** Плашка «Демо: заявка не отправлена», сводка
   того, что ушло бы в центр (программа, имя, телефон, e-mail, метка,
   «Telegram, мини-приложение»), кнопка «Вернуться к программам». Главная
   кнопка: «Перейти к оплате на hse.ru» – открывает `pay` через
   `Telegram.WebApp.openLink`.

### 3.4 Telegram и обычный браузер

Внутри Telegram: `ready()`, `expand()`, цвет шапки и фона листа
`#FBF9F5` (`setHeaderColor`, `setBackgroundColor`), нативные `MainButton` и
`BackButton`, `HapticFeedback` на отправке. Вне Telegram (нет
`window.Telegram.WebApp.initData`) те же экраны показывают свою кнопку внизу
и свою кнопку «назад» в шапке страницы.

`telegram-web-app.js` грузится с `https://telegram.org/js/telegram-web-app.js`
без SRI: Telegram обновляет файл по тому же адресу. Свой `js/tg-app.js`
подключается через `scriptTag` из `lib/sri.js` с integrity. CSP страницы:
`default-src 'none'; script-src 'self' https://telegram.org; style-src 'self';
img-src 'self' data:; font-src 'self'; base-uri 'self'; form-action 'none'`,
без `'unsafe-inline'`. Поэтому обложки – элементы `<img>`, а не
`style="background-image"`, и на странице нет инлайн-стилей и обработчиков.

### 3.5 Параметр `startapp`

Telegram пропускает `[A-Za-z0-9_-]`, до 512 символов. Источник –
`Telegram.WebApp.initDataUnsafe.start_param`, вне Telegram – `?startapp=` в
адресе страницы.

Формат – части через `-`:

- `p_<id>` – открыть программу с этим id (стек: витрина → программа);
- `c_<метка>` – метка кампании, `[A-Za-z0-9_]{1,64}`.

Примеры: `p_494685723`, `c_yuriy2`, `p_494685723-c_yuriy2`. Неизвестная
часть, несуществующий id, лишние символы или длина больше 512 молча
игнорируются – открывается витрина.

## 4. Облик

Направление А: облик сайта по `DESIGN.md` без поправки на тему Telegram.
Токены – из `programs/program.css` (`--bg #FBF9F5`, `--bg-tint #F2ECE1`,
`--ink`, `--ink-soft`, `--ink-mute`, `--accent #1658DA`, `--line`), шрифты
HSE Sans и HSE Slab из `fonts/`. Заголовки слэб-серифные, один синий
акцент, без теней в покое, скругления карточек 14px, кнопок 12px, чипы на
пергаменте, активный чип – тёмный. Эталон – экраны направления А во
временном макете `programs/_tg-mockup.html` (удаляется после согласования
спецификации).

В `DESIGN.md` добавляется раздел компонента «Мини-апп Telegram»: решение
А, токены и движение.

### 4.1 Движение

- переход вперёд: экран въезжает `translateX(28px)` + прозрачность,
  340 мс, `cubic-bezier(.22,1,.36,1)`; назад – с `-20px`;
- каскад карточек витрины: подъём на 10px, 420 мс, шаг 45 мс, не больше
  8 ступеней – **только при входе на витрину**, не при смене сферы и не при
  вводе в поиске;
- нажатие: карточка `scale(.985)`, кнопки и чипы `scale(.97)`, 120 мс;
- плашка демо-экрана поднимается с задержкой 80 мс;
- `prefers-reduced-motion: reduce` отключает всё.

1. `@BotFather`: `/newbot`, имя и username бота.
2. Bot Settings → Configure Mini App → Main App:
   `https://itspecr.github.io/dpo-pravo-hse/tg/`.
3. Прислать username бота. Токен не нужен и не пересылается.

## 7. Второй этап (не сейчас)

Приём заявки: `POST` в `intake-server.js` с `initData`, сервер проверяет
HMAC-подпись токеном бота и срок `auth_date`, заявка идёт по тому же пути
(журнал, письмо, вкладка «Заявки») с источником «Telegram» и меткой
кампании. Уведомление менеджерам в чат. Боевой HTTPS-адрес вместо зеркала.
